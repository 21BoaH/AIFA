# AI Fitness Assistant — Android and iOS apps

The apps are built with [Capacitor](https://capacitorjs.com/) 8, a cross-platform runtime that packages one web
codebase as native Android and iOS apps. They run the **same pages and the same tracker code as the website**
(`../AIFitnessAsisstant`), so every exercise, rule and fix lands in the site and both apps at once.

- **Works offline.** MediaPipe Pose (the model, its WebAssembly and the helper scripts) and the fonts are bundled
  in the app. Nothing loads from the internet.
- **Private.** The camera is read inside the app; video is never recorded or uploaded.
- **Native touches.** App icon and splash screen. Content stays clear of the notch, status bar and gesture bar.
  The screen stays on during a set, and the Android back button works as expected.

## Get the Android app

Every push to `main` that changes the site or the app builds a debug APK on GitHub Actions:

1. Open the repository's **Actions** tab, then **Build mobile apps**, then the latest successful run.
2. Under **Artifacts**, download **ai-fitness-assistant-android** and unzip it to get `app-debug.apk`.
3. Copy the APK to an Android phone (Android 7.0 or later) and open it. Allow installs from that source when
   Android asks. Then allow camera access the first time you press **Start**.

## Run it on an iPhone

Installing on an iPhone needs your Apple account to sign the app, so it is done from Xcode on a Mac:

1. Install Node.js 22 and Xcode 26 or later.
2. Run `npm ci` in `mobile/`, then `npm run ios`. This builds the web content, copies it in and opens Xcode.
3. In Xcode, select the **App** target, open **Signing & Capabilities** and choose your **Team**. A free Apple ID
   works for your own phone; apps signed that way expire after 7 days.
4. Connect the iPhone (iOS 15 or later), select it as the run destination and press **Run**.

The Actions run also builds the iOS app for the simulator (**ai-fitness-assistant-ios-simulator**). That build
proves the Xcode project compiles; it can't be installed on a phone.

## Build it yourself

| Platform | You need |
|---|---|
| Android | Node.js 22, JDK 21 and Android Studio (SDK 36) |
| iOS | Node.js 22 and Xcode 26 or later, on a Mac |

```bash
cd mobile
npm ci
npm run android   # build www/, sync, and open Android Studio (then Run)
npm run ios       # build www/, sync, and open Xcode (macOS)
npm run sync      # just rebuild www/ and copy it into both native projects
```

After changing anything in `../AIFitnessAsisstant`, run `npm run sync` (or let CI do it) so the apps pick it up.

## How it works

| Path | What it is |
|---|---|
| `scripts/build-web.mjs` | Builds `www/` from the site (see below) |
| `src/app.css`, `src/app.js` | The app shell: safe areas, touch polish, back button, keep-awake |
| `capacitor.config.json` | App id, name, background colour, edge-to-edge handling |
| `android/`, `ios/` | The native projects (generated by Capacitor, then configured; commit changes to them) |
| `assets/`, `scripts/make-icon-sources.mjs` | Icon and splash sources, rendered from the site's brand mark |
| `www/` | Build output, not committed |

`npm run build` copies the site's pages and assets into `www/` and changes only what an app needs:

- **Bundled dependencies.** MediaPipe comes from the same npm releases the site loads from the CDN: the full
  pose model, with SIMD and non-SIMD WebAssembly. Archivo and JetBrains Mono come from Fontsource.
- **Edge to edge.** Every page gets `viewport-fit=cover`, plus `app.css` and `app.js`.
- **Wording.** "Click Start" becomes "Tap Start".
- **Safety check.** The build fails if any page would still load something from the internet.

Native configuration on top of the Capacitor templates:

- **Android:** the `CAMERA` permission (the camera itself is optional to install), and a dark window behind the
  system bars.
- **iOS:** the camera usage description shown in the permission prompt, and dark appearance.
- **Both platforms:** WebView camera access is granted by Capacitor once the system permission is given.
- **Plugins:** `@capacitor/app` handles the back button. `@capacitor-community/keep-awake` keeps the screen on
  while a tracker's camera runs.

## Before publishing to the stores

- **App id.** It is `com.aifa.fitnessassistant`. Pick your own before the first release, because a store listing
  can't change it later. Change it in these places:
  - `capacitor.config.json`;
  - `android/app/build.gradle` (`namespace` and `applicationId`), and move `MainActivity.java` to the matching
    package folder;
  - the iOS target's Bundle Identifier in Xcode.
- **Android:** create an upload keystore, then build a signed App Bundle in Android Studio (**Build ▸ Generate
  Signed App Bundle**) and upload it in the Google Play Console.
- **iOS:** join the Apple Developer Program. In Xcode, use **Product ▸ Archive**, then distribute to App Store
  Connect (TestFlight first).
- **Icons:** to change them, edit `scripts/make-icon-sources.mjs` (or replace the files in `assets/`), then run
  `npm run icons && npm run assets`.
- **Version:** bump `versionCode` and `versionName` in `android/app/build.gradle`, and the iOS version and build
  in Xcode.

## Testing

What has been tested:

- The app's web content passes the same 100 synthetic tracker scenarios as the site.
- It ran with the real MediaPipe model and every internet request blocked: no external requests, no missing files,
  bundled fonts in use, and tracking across Start, Stop and Start again.
- Safe-area padding was checked at phone size with simulated notch and gesture-bar insets.

What hasn't been tested yet:

- The native builds compile on GitHub Actions. They haven't been run on physical phones.
- Camera performance depends on the phone, and the pose model is the heaviest part.
